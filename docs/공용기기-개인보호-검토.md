# 공용 기기 개인 보호 검토

검토일: 2026-10-30. 결론부터 적으면, **이번에는 기능을 더하지 않고 현재 방식(목록 접기 + 파일 백업 + 전체 삭제)을 유지합니다.** 아래는 그렇게 정한 이유와, 나중에 더한다면 어떤 방식이 가능한지에 대한 기록입니다.

## 지금의 동작

- 작품은 기기 브라우저의 IndexedDB에 저장합니다. 학생 계정·서버가 없습니다.
- **다음 사용자 시작**은 기존 작품을 지우지 않고 목록에서 접고, 최근 작품 연결과 되돌리기 기록을 비웁니다. 접힌 작품은 **공용 기기 기록을 명시적으로 열기**로 누구나 다시 열 수 있습니다.
- **이 앱의 데이터 전체 삭제**는 이 앱의 작품·설정·학급 평가 목록·되돌리기 기록을 지웁니다.
- 화면과 README, 교사 안내서에 "로그인이나 개인별 비밀 보호가 아닙니다"라고 알립니다.

즉 지금의 보호는 **실수로 남의 작품을 이어서 고치지 않게 하는 정도**이며, 같은 기기를 쓰는 사람이 마음먹고 보려는 것을 막지는 못합니다.

## 검토한 방식

| 방식 | 하는 일 | 막을 수 있는 것 | 막지 못하는 것 · 비용 |
|---|---|---|---|
| A. 지금 방식 유지 | 목록 접기, 파일 백업, 전체 삭제 | 실수로 이어 쓰기 | 일부러 열어 보기 |
| B. 작품별 짧은 비밀번호(잠금 화면만) | 열기 전에 숫자 4자리를 묻고, 저장값은 그대로 | 화면에서 무심코 열기 | 개발자 도구·백업 파일로 바로 읽힘. "잠겨 있다"는 잘못된 안심을 줌 |
| C. 작품별 비밀번호 + 암호화 저장 | 비밀번호에서 키를 만들어(PBKDF2 등) 작품 내용을 AES-GCM으로 암호화 | 같은 기기의 다른 사용자가 내용 읽기 | 비밀번호를 잊으면 **복구 불가**(서버가 없어 재설정 못 함). 초등학생 비밀번호는 짧아 무차별 대입에 약함. 백업·친구 검사·학급 모으기 파일 형식이 모두 바뀜. 교사가 학생 작품을 평가하려면 비밀번호를 알아야 함 |
| D. 기기별 학생 칸(프로필) | 시작할 때 이름 카드를 골라 자기 칸만 보이기 | 실수로 남의 칸 열기 | 보호는 A와 같음. 이름이 기기에 남아 오히려 개인 정보가 늘어남 |
| E. 수업 끝 자동 정리 | 정해진 시간이 지나거나 탭을 닫으면 백업을 권하고 지우기 | 다음 시간 사람이 보기 | 백업을 안 한 학생의 기록이 사라질 위험. 브라우저가 탭 닫기 직전 확인을 막는 경우가 있음 |
| F. 학교 계정 로그인 | 서버에 학생별로 저장 | 대부분의 공유 문제 | 서버·개인 정보 처리 방침·보호자 동의 등 운영 부담. 이 앱의 "가입 없이, 서버 없이" 원칙과 다름 |

## 이번에 더하지 않은 이유

1. **B는 보호처럼 보이지만 보호가 아닙니다.** 잘못된 안심이 지금의 솔직한 안내보다 위험하다고 판단했습니다.
2. **C는 실제 보호가 되지만 수업 운영 비용이 큽니다.** 비밀번호를 잊은 학생의 작품은 교사도 되살릴 수 없고, 친구 검사·학급 평가처럼 파일을 주고받는 활동이 모두 비밀번호를 거쳐야 합니다. 3~6학년 수업에서 감당하기 어렵습니다.
3. **이 앱이 받는 내용은 개인 정보가 아니도록 설계했습니다.** 이름 칸은 "이름이나 별명"이고, 학생 작품은 퀴즈·이야기·타이머·패턴 설정과 학습 기록입니다. 교사 안내서와 보충 안내에서 개인 정보를 적지 않도록 지도하게 했습니다.

## 지금 권하는 운영

- 수업이 끝나면 **목록 백업**으로 파일을 받아 학급 드라이브 등 학교가 정한 곳에 보관합니다.
- 다음 반이 쓰기 전에 **다음 사용자 시작**, 기기를 반납하거나 학기가 끝나면 **이 앱의 데이터 전체 삭제**를 누릅니다.
- 개인 기기를 쓰는 학급은 위 걱정이 줄어듭니다. 공용 기기라면 학생이 자기 이름 대신 별명을 쓰게 합니다.

## 다시 검토할 때의 조건

다음 가운데 하나가 생기면 C(암호화 저장)나 F(학교 계정)를 다시 검토합니다.

- 학생이 사진·음성·실명 등 개인 정보를 작품에 넣는 기능을 더할 때
- 학교가 공용 기기에서 학생별 기록 분리를 요구할 때
- 교사가 비밀번호 없이도 평가할 수 있는 방법(예: 교사용 복구 키를 학급마다 따로 두기)을 안전하게 설계할 수 있을 때

C를 구현한다면 Web Crypto API(PBKDF2로 키 만들기, AES-GCM 암호화)만으로 서버 없이 가능하며, 저장 형식 버전을 올리고(`src/storage.ts`의 변환 단계 추가), 백업 파일에 "잠긴 작품" 형식을 따로 두어야 합니다. 비밀번호 분실 시 복구할 수 없다는 점을 화면에서 먼저 동의받아야 합니다.
