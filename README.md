# 뚝딱 바이브 공작소

초등 5~6학년과 일반 입문자가 **목표 → 요청 → 예상·실행 → 검사·수정 → 설명·저장**을 경험하는 정적 교육용 웹앱입니다. 퀴즈·갈림길 이야기·타이머의 실행기 3개를 12개 미션에서 재사용합니다. 3~4학년은 선택 카드와 짝 활동으로 참여할 수 있습니다.

**[웹앱 바로 열기](https://gmlduqzhd123-lab.github.io/Vibe-for-U/)** · [GitHub 저장소](https://github.com/gmlduqzhd123-lab/Vibe-for-U) · [GitHub 연동·공개 검증](docs/GITHUB-연동.md)

학생·교사 체험을 바탕으로 약속 확인, 검사 준비, 단계 이동, 차시별 미션 연결과 인쇄를 개선했습니다. [UX 개선 기록](docs/UX-개선.md)에서 변경 이유와 검증 범위를 확인할 수 있습니다.

## 바로 실행

Node.js 24와 npm을 사용합니다. 이 프로젝트 폴더에서 실행하세요.

```powershell
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 엽니다. 인터넷 서비스나 계정·API 키 설정은 필요하지 않습니다. 설치 시에만 npm 패키지를 받습니다.

```powershell
npm run build   # TypeScript 검사 + dist/ 정적 산출물
npm run preview # 빌드한 앱 미리보기
npm test        # 핵심 규칙·저장·가져오기 자동 테스트
npm run test:e2e # 빌드 후 Windows Edge 브라우저 검사
npx playwright test -c playwright.public.config.ts # 실제 공개 주소에서 같은 흐름 검사
```

브라우저 검사는 설치된 Microsoft Edge를 사용합니다. 테스트가 필요하면 `npm run build`를 먼저 실행하세요. Playwright가 `scripts/serve.mjs`를 열어 실제 `dist/`를 **`/pages-check/` 하위 경로**에서 제공합니다. 테스트 서버는 제품의 필수 서버가 아닌 개발·검증 도구입니다. 배포물은 정적 파일만 필요합니다.

## 첫 시범: 중복 점수 고치기

1. 미션 공작대에서 **퀴즈 3 · 어라? 점수가 또 올라가요!**를 엽니다.
2. 목표와 약속 예시를 내 생각에 맞게 고치고 **이 약속으로 만들기**로 확인합니다. 내 원문을 쓴 뒤 요청문을 정리합니다.
3. 예상에 “같은 정답을 세 번 눌러도 1점”을 적습니다. 오른쪽 퀴즈에서 첫 정답을 세 번 누르면 학습용 규칙에 따라 3점이 됩니다.
4. 검사 단계의 **현재 설정 자동 검사**를 누르면 자동 결과와 직접 확인 카드가 함께 준비됩니다. 직접 눌러 실제 결과를 적고 확인 상태를 선택합니다. 아래 버전 패널에서 수정 전 상태를 남길 수 있습니다.
5. 실행 단계로 돌아가 채점 규칙을 **문제당 한 번**으로 바꿉니다. 같은 행동을 해도 1점입니다.
6. 새 설정에서 다시 검사하고, 직접 본 결과와 수정 이유를 씁니다. 마지막 단계에서 작동 원리와 도움받은 내용을 적고 버전을 저장합니다.
7. 포트폴리오에서 수정 전후 기록을 읽고 인쇄하거나 작품 파일로 백업합니다.

**일반 새 작품**은 정상 규칙으로 시작합니다. 학습용 오류는 허용된 설정으로 재현하며 공통 실행기를 손상시키지 않습니다.

## 화면과 안내 모드

홈은 선택한 **1안 역할 선택형**을 적용했습니다. **학생으로 시작**은 3분 체험, **교사로 시작**은 40분 수업 준비로 바로 연결됩니다. **이어서 만들기**는 최근 작품이 있으면 그 작품을 열고, 없으면 작품 선반을 엽니다. 상단 **전체 메뉴**에서 완성 예제·전체 미션·작품 선반·교사 자료·QR 카드·첫 작품 만들기·안내 모드에 접근합니다. 예제·다섯 단계 그림·쉬운 용어·수정 전후 비교는 완성 예제 화면에서, 교과별 활용과 차시 준비는 교사 수업 준비에서 제공합니다. [1안 채택과 검증](docs/홈-간소화-시안.md), [10가지 개선의 현재 위치](docs/첫방문-개선.md)를 참고하세요.

- 홈: 학생·교사 두 입구, 이어서 만들기, 접힌 전체 메뉴
- 미션: 세 프로젝트마다 네 가지 목표·예상·검사·수정·힌트·완료 기준
- 작업실: 다섯 단계와 실행 미리보기, 설정 편집, 원리·상태 설명
- 작품 선반: 다시 열기, 백업·가져오기, 삭제, 공용 기기 정리
- 버전 패널: 설정·요청문·예상·검사·수정 이유를 묶어서 비교·복원
- 포트폴리오: 실제 기록을 모은 인쇄용 화면
- 공개 교사 자료실: 40분 × 8차시, 짝 역할 교대, 검사표, 네 항목·세 단계 과정 평가표, 학급 작품 모으기, 시범 작품

일반 입문자 모드는 캐릭터와 장식을 줄이고 도움말을 접습니다. 모드를 바꿔도 작품과 기록은 유지됩니다. 교사 자료실은 공개 자료이며 모드 선택은 교사 인증이 아닙니다.

단계 표시는 기록이 채워졌는지를 보여 줍니다. 문장의 의미·창의성·이해도를 자동 채점하지 않습니다. 검사 단계에는 직접 관찰 기록도 필요합니다. 자동 검사, 학습자 직접 확인, 친구·교사 의견, 미확인을 별도로 표시하며 예전 설정의 검사로 현재 설정을 완료 처리하지 않습니다.

새 작품의 약속은 예시를 읽고 확인하기 전까지 완료하지 않습니다. 퀴즈 점수와 이야기 장면은 같은 작품의 단계·활동 전환에서 유지되고, 설정 변경·작품 다시 열기·버전 복원 시 실행 상태는 초기화합니다. 타이머는 화면·단계 이동에서 실행을 정리합니다. 예상을 수정하면 그 예상으로 다시 실행해야 기록 완료가 됩니다. 재검사는 현재 설정의 자동 결과를 갱신하고 직접 쓴 관찰과 이전 설정의 기록을 유지합니다.

교사는 각 차시의 연결 미션을 열거나 학생용 주소를 복사할 수 있습니다. 인쇄용 검사표는 프로젝트별로 골라 사용하며, 기대 결과는 정상 규칙의 예시이고 실제 결과는 관찰 후 직접 기록합니다. 포트폴리오는 사람이 읽는 규칙 요약을 인쇄하고 원본 JSON 설정은 화면에서 선택하여 펼쳐 볼 수 있습니다.

## 교사용 안내서와 학생 활동지

**교사 자료실 → 8차시 수업 안내 → 수업 자료 내려받기**에서 교사용 안내서(14쪽)와 학생 활동지 합본(16쪽)을 PDF로 열거나 내려받을 수 있습니다. Word 수정본과 전체 ZIP 묶음도 제공합니다. 각 차시를 펼치면 해당 차시의 앞뒤 2쪽짜리 활동지를 따로 열고 받을 수 있습니다.

학생 활동지는 한 면당 한 쪽으로 인쇄하고, 양면 인쇄 시 긴 쪽 넘김을 선택합니다. 각 차시 PDF의 쪽번호는 합본의 쪽번호를 유지합니다. **화면 안내 인쇄**는 자료실의 웹 화면을 인쇄하며, PDF 인쇄는 **PDF 열기**에서 합니다. 6차시의 외부 AI 도구는 교사·성인이 조작합니다.

자료 파일은 `public/materials/`에 포함되어 정적 Pages 배포에서 함께 제공됩니다. 학습 화면 진입 시 문서를 미리 다운로드하지 않으며, 사용자가 선택한 파일만 요청합니다. 파일 URL은 Vite의 배포 기준 경로를 따라 저장소 하위 경로에서도 열립니다. 학생 작품·학습 기록은 제공 파일에 포함되지 않습니다.

자료를 갱신할 때는 PDF·Word 합본, 차시별 2쪽 PDF 8개, ZIP 내부 파일을 함께 갱신하고 `src/Pages.tsx`의 쪽수 안내를 확인하세요. 원본 합본 16쪽과 분리한 16쪽은 렌더 이미지가 동일한지 확인했습니다. 상세한 연결 검사는 [수업 자료 연결 검증](docs/수업자료-연결.md)을 참고하세요.

## 학급 작품 모으기와 과정 평가

**교사 자료실 → 학급 작품 모으기**에서 서버 없이 학급의 작품을 모아 봅니다.

1. 학생은 **내 작품 선반 → 목록 백업** 또는 작업실의 **파일 백업**으로 JSON 파일을 냅니다(메신저·USB·학교 드라이브 등). 파일 이름을 번호·이름으로 바꿔 받으면 알아보기 쉽습니다.
2. 교사는 **학생 작품 파일 고르기**로 여러 파일을 한꺼번에 엽니다. 가져오기와 같은 검사를 거치며, 읽지 못한 파일은 이유와 함께 따로 표시합니다.
3. **한눈에 보기** 표에서 작품별 다섯 단계 기록, 직접 확인한 검사, 재검사, 버전 수와 단계별 완료 인원을 봅니다.
4. 작품 카드를 펼치면 예상·수정 이유·직접 검사·성찰을 근거로 과정 평가표 네 항목에 단계(미평가·시작·수행·설명·적용)를 매기고 의견을 적습니다.
5. **표 CSV로 내려받기**는 표와 평가를 엑셀에서 열 수 있게 저장합니다(한글 BOM, `=`·`+`·`-`·`@`로 시작하는 칸은 수식으로 실행되지 않게 처리). **평가를 넣은 작품 파일**을 학생에게 돌려주면, 학생이 **파일 가져오기**로 열었을 때 포트폴리오의 **선생님의 과정 평가**에 나옵니다.

모은 파일은 이 화면에서만 읽고 교사 기기의 저장소나 서버에 넣지 않습니다. 새로고침하면 사라지므로 평가를 마치면 CSV나 평가 파일로 내려받으세요. 평가는 기록을 근거로 교사가 직접 매기며, 앱이 자동으로 점수를 매기지 않습니다.

## 기본 연습과 실제 AI

기본 연습실은 **준비된 코드와 확인한 설정·규칙**을 실행합니다. 자유롭게 쓴 요청문을 코드로 실행하거나 실제 AI 생성으로 표현하지 않습니다.

실제 AI 활동에서는 학생이 요청·예상·검사를 작성하고, 교사·성인이 외부 AI 개발 도구에 복사하여 생성·실행합니다. 도구명·도움·기대·관찰·판정·수정 요청은 별도 기록입니다. 복사만으로 완료되지 않으며, 이 앱의 자동 검사는 외부 AI 코드를 검증하지 않습니다. 외부 도구 사용에는 해당 도구의 환경과 교사 판단이 필요합니다.

## 저장·백업·공용 기기

- IndexedDB `ttukttak-vibe:works-v1`의 `works` 저장소에 작품·버전·검사를 보관합니다.
- `ttukttak-vibe:`로 시작하는 localStorage 키에는 모드·최근 작품·다음 사용자 목록 설정만 넣습니다.
- 편집은 약 400ms 뒤 자동 저장하며, IndexedDB 트랜잭션 완료 후에만 저장됨으로 표시합니다. 단계 이동 때도 저장을 요청합니다. 미저장 내용이 있으면 탭 종료 시 브라우저 확인을 요청합니다.
- 버전 저장은 자동 저장과 별개입니다. 이전 버전 복원 전 편집본도 새 버전으로 보존합니다. 처음 시작 버전은 유지하고, 다른 버전은 백업 후 개별 삭제할 수 있습니다.
- 저장 실패 시 입력을 화면에 유지하고 오류·재시도·JSON 백업을 제공합니다. 브라우저 데이터 삭제나 기기 고장에 대비해 파일 백업을 보관하세요.
- 다른 브라우저·기기·출처에서는 같은 IndexedDB에 접근하지 못합니다. 작품 JSON을 내보내서 가져오세요.
- 작품 삭제, 선택 검사 기록 삭제, 앱 전체 데이터 삭제의 범위를 확인하고 백업할 수 있습니다. 전체 삭제도 다른 앱의 저장소를 지우지 않습니다.
- 다음 사용자 시작은 기존 작품을 지우지 않고 목록에서 접으며 최근 작품 연결을 비웁니다. 공용 기록은 명시적으로 다시 열 수 있습니다. **로그인이나 개인별 비밀 보호가 아닙니다.**

## 파일 제한과 검사

공통 상수는 `src/model.ts`의 `LIMITS`, 검증은 `src/storage.ts`에 있습니다.

| 항목 | 제한 |
|---|---|
| 파일 | JSON, 스키마 버전 1~2(1은 읽을 때 2로 변환), 2MiB(안내상 2MB) 이하 |
| 한 파일의 작품 | 최대 50개 |
| 작품별 버전 | 시작 버전 포함 30개, 버전 묶음 600KiB 이하 |
| 편집본·각 버전의 검사 | 최대 100개 |
| 문항 / 장면 | 각각 20개 / 24개 |
| 선택지 | 문항·장면마다 최대 6개, 퀴즈는 최소 2개 |
| 일반 글 / 제목·선택 문장 | 4,000자 / 200자 |
| 만들기 약속 / 검사 기대·실제 | 각 500자 |
| 타이머 / 문제당 점수 | 1~3,600초 / 1~10점 |

목록 백업이 2MB나 50작품을 넘으면 번호를 붙인 여러 파일로 나눕니다. 브라우저가 여러 다운로드 허용을 요청하면 허용하고 모든 파일을 보관하세요. 파일은 하나씩 가져올 수 있습니다. 가져온 작품에는 항상 새 ID를 부여합니다.

가져오기는 모든 버전의 자료형·길이·범위·개수·중복 이름표와 장면 참조까지 검사한 뒤 하나의 트랜잭션으로 저장합니다. 실패하면 기존 작품을 변경하지 않습니다. 파일의 문자열은 React 텍스트로 표시하고 HTML이나 실행 코드로 평가하지 않습니다.

## GitHub Pages 배포

연결 저장소는 [gmlduqzhd123-lab/Vibe-for-U](https://github.com/gmlduqzhd123-lab/Vibe-for-U), 기본 브랜치는 `main`입니다. 첫 연결 시 빈 공개 저장소임을 확인했습니다. 이 앱 폴더의 `origin`을 해당 저장소에 연결했고, `main` 푸시와 수동 실행으로 Pages 워크플로가 작동합니다. Pages의 게시 원본은 GitHub Actions입니다. 최초 배포 성공과 공개 주소 HTTP 200을 확인했습니다. 상세 근거는 [연동 기록](docs/GITHUB-연동.md)에 있습니다.

1. 저장소를 복제하거나 이 연결된 프로젝트 폴더에서 작업합니다. 기존 프로젝트와 합칠 때는 기존 앱과 Actions 설정을 먼저 확인하세요.
2. 저장소 **Settings → Pages → Source**에서 **GitHub Actions**를 선택합니다.
3. 기본 브랜치에 `.github/workflows/pages.yml`을 포함합니다.
4. `main`에 푸시하거나 **Actions → Build and deploy GitHub Pages → Run workflow**를 실행합니다.
5. 성공한 `deploy` 작업의 `page_url`과 실제 공개 페이지를 확인합니다. 이 주소가 해당 저장소의 실제 배포 주소입니다.

Vite `base: './'`와 해시 라우팅을 사용하여 저장소 하위 경로에서도 자산을 상대 경로로 읽습니다. 미션·작품 화면을 새로고침해도 서버에는 `index.html`이 있는 경로만 요청합니다. 사용자 기록은 공유 링크에 넣지 않습니다. 저장된 작품 URL은 그 기기의 자료를 여는 주소이며 작품의 공개 게시 주소가 아닙니다.

워크플로는 테스트 → 빌드 → Pages 설정 → `dist/` 업로드 → 배포 순서입니다. 참고: [GitHub 공식 사용자 지정 Pages 워크플로 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### 저장 형식 버전과 변환

현재 저장 형식은 **스키마 버전 2**(`src/model.ts`의 `SCHEMA_VERSION`)입니다. 버전 2는 버전 1에 교사 평가 기록(`feedback`)을 더했습니다.

- 가져오기와 기기 저장소 읽기는 모두 `src/storage.ts`의 `migrateWork`를 거칩니다. 옛 버전 작품은 `migrations` 표의 함수를 차례로 적용해 현재 버전으로 바꾼 뒤, 현재 형식 기준으로 한 번 검사합니다. 기기에 남은 옛 작품은 다음 저장 때 새 형식으로 기록됩니다.
- 이 앱보다 새로운 버전의 파일은 "더 새로운 앱에서 만든 파일"이라고 알리고 거절하며, 기존 작품은 바꾸지 않습니다. 이전 배포본은 버전 2 파일을 읽지 못하므로 최신 주소에서 열어야 합니다.
- 형식을 다시 바꿀 때: `SCHEMA_VERSION`을 1 올리고 → `migrations[이전 버전]`에 변환 함수를 더하고 → `Work` 타입과 `validateWork`를 고치고 → `tests/schema.test.ts`에 옛 버전 파일의 변환 테스트를 추가합니다. 변환 함수는 지우지 않습니다.

## 검증 범위와 제약

최초 로컬 검사 결과와 수정 내역은 [검증 결과](docs/검증결과.md), 이후 공개 배포 검증은 [연동 기록](docs/GITHUB-연동.md)에 있습니다. Windows의 실제 Edge 엔진에서 PC·태블릿·휴대전화 크기를 에뮬레이션했습니다. 실제 휴대전화·학교 기기·Safari·교사 수업 운영·물리 프린터 검증은 별도입니다. 브라우저 저장소를 허용해야 기기 저장이 가능합니다. 같은 작품을 여러 탭에서 열면 한 탭만 편집하고 나머지 탭은 읽기 전용으로 엽니다(Web Locks). 읽기 전용 탭에서 **이 탭에서 편집하기**를 누르면 편집 권한을 넘겨받고, 편집하던 탭이 작품을 떠나거나 닫히면 남은 탭이 이어받습니다. 저장·삭제는 다른 탭에 알려 목록과 읽기 전용 화면을 새로 읽습니다(BroadcastChannel). Web Locks가 없는 오래된 브라우저에서는 예전처럼 모든 탭에서 편집할 수 있으니 한 탭만 사용하세요. 실시간 공동 편집·충돌 병합은 지원하지 않습니다.

공유는 같은 미션 링크, 작품 파일, 인쇄용 기록, 교사의 파일 모으기입니다. 계정·서버·외부 DB·자동 학급 수합·순위·실시간 공동 편집·임의 HTML/JS 실행·카메라·마이크·위치는 도입하지 않았습니다. 한 번이라도 인터넷에 연결해 연 기기는 이후 오프라인에서도 앱을 열 수 있습니다(아래 **오프라인 사용** 참고). 한 번도 연 적 없는 기기의 첫 접속에는 인터넷이 필요합니다.

## 오프라인 사용

배포판은 서비스 워커(`public/sw.js`)를 등록하고 홈 화면 설치를 안내합니다(`public/ys-install.js`).

- 빌드할 때 `scripts/precache.mjs`가 `dist/`의 화면 실행 파일(JS·CSS 번들, `index.html`, 아이콘, 안내 그림)을 미리 받을 목록에 넣습니다. 캐시 이름에는 파일 내용의 해시를 붙여 배포할 때마다 새 이름이 되고, 예전 `vibe-for-u-v*` 캐시는 새 서비스 워커가 정리합니다. 같은 주소의 다른 앱 캐시는 건드리지 않습니다.
- 수업 자료(`materials/`)·디자인 시안(`concepts/`)·공유 이미지는 미리 받지 않습니다. 한 번 열어 본 파일만 캐시에 남습니다.
- 요청은 인터넷을 먼저 사용하고, 연결이 끊기면 캐시로 응답합니다.
- 이미 쓰던 기기에 새 배포본이 설치되면 화면 위쪽에 **저장하고 새로고침** 안내가 나옵니다. 편집 내용을 먼저 저장한 뒤 다시 불러오며, 저절로 새로고침하지 않습니다.
